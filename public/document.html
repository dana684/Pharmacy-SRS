المتطلبات الوظيفية

07 · FR-001 إلى FR-070

افتح كل مجموعة لعرض المتطلبات التفصيلية ومعرّفاتها.

الحسابات والعملاء · FR-001–FR-006
  • التصفح متاح للزائر، والشراء يتطلب حساباً وتسجيل الدخول.
  • التسجيل والدخول برقم الهاتف وكلمة المرور.
  • التحقق من الهاتف عبر OTP عند التسجيل وتغيير الرقم.
  • استعادة كلمة المرور عبر الهاتف بعد التحقق.
  • تعديل البيانات الشخصية وكلمة المرور وبيانات التواصل.
  • عنوان توصيل واحد محفوظ قابل للتعديل ويستخدم افتراضياً.
المنتجات والبيانات الصيدلانية · FR-007–FR-015
  • إضافة المنتجات وتعديلها وحذفها يدوياً.
  • استيراد المنتجات من Excel وتصدير بيانات المنتجات إليه.
  • دعم Barcode وSKU ورفع صور متعددة.
  • تعديل الأسعار والكميات وإدارة المنتجات والعروض جماعياً.
  • دعم المنتج المستقل أو المنتج ذي Variants، ويختار المسؤول النمط لكل منتج.
  • حقول مشتركة أساسية وحقول ديناميكية بحسب الفئة.
  • تخصيص الحقول الديناميكية من الإدارة بأنواع نص ورقم وقائمة واختيارات وباللغتين.
  • الاسم التجاري والعلمي والشركة المصنعة وبلد المنشأ والتركيز/الحجم والشكل الصيدلاني والمكونات وطريقة الاستخدام والتحذيرات والتخزين حسب الفئة.
  • الدفعة وتاريخ الصلاحية ليسا حقولاً إلزامية عامة لكل منتج.
البحث والتصفح · FR-016–FR-020
  • البحث بالعربية والإنجليزية والاسم التجاري والعلمي وBarcode وSKU.
  • اقتراحات بحث تلقائية Autocomplete.
  • فلترة بالتصنيف والعلامة التجارية والسعر والتوفر.
  • ترتيب بالسعر أو الاسم أو الأحدث.
  • إظهار المنتج غير المتوفر بعبارة «انتهت الكمية» وتعطيل الإضافة للسلة.
السلة والطلبات · FR-021–FR-031
  • إضافة المنتجات للسلة وتعديل الكميات أو حذفها.
  • التحقق من المخزون على الخادم عند الإضافة وإرسال الطلب.
  • استخدام عنوان العميل المحفوظ افتراضياً.
  • عرض ملخص الأسعار والخصومات ورسوم التوصيل والإجمالي بـ SYP.
  • تسجيل الطلب Pending بعد الإرسال.
  • مراجعة الإدارة للتوفر والبيانات والموافقة أو الرفض مع السبب.
  • بعد الموافقة ينتقل الطلب إلى Confirmed ثم Processing حسب مسار الدفع.
  • إشعار العميل عند تغير حالة الطلب.
  • إلغاء العميل للطلب مسموح قبل بدء التجهيز فقط.
  • عرض سجل الطلبات وتفاصيل كل طلب وفاتورته.
  • إعادة طلب سابق مع التحقق من السعر والتوفر الحاليين.
الوصفات الطبية · FR-032–FR-037
  • رفع صورة وصفة عند طلب دواء يتطلب وصفة.
  • مراجعة الصيدلي للوصفة والموافقة أو الرفض مع السبب.
  • مراجعة دواء الوصفة مستقلة عن بقية عناصر الطلب.
  • عند رفض دواء يُلغى هذا الدواء فقط ويعاد احتساب الطلب.
  • إشعار العميل بسبب الرفض وإعادة حساب رسوم التوصيل والإجمالي عند الحاجة.
  • حماية ملفات الوصفات وتقييد الوصول للمخولين.
الدفع والاسترداد · FR-038–FR-048
  • دعم الدفع نقداً عند الاستلام، وشام كاش، وسيرياتل كاش.
  • الدفع الإلكتروني بعد موافقة الإدارة وإشعار العميل.
  • التحقق الآلي عبر API رسمي عند توفره والتصريح باستخدامه؛ وإلا تحقق إداري موثق.
  • بدء التجهيز بعد نجاح الدفع الإلكتروني.
  • مدير الصيدلية يحدد مهلة الدفع الإلكتروني ويعدلها.
  • انتهاء المهلة دون تأكيد يؤدي إلى إلغاء تلقائي وتحرير الكميات وإشعار العميل.
  • مهلة الدفع لا تنطبق على الدفع عند الاستلام.
  • الاسترداد آلي عبر API إن توفر، وإلا يدوياً من الإدارة.
  • تسجيل مبلغ الاسترداد وسببه وتاريخه وربطه بالطلب والدفع وحالاته.
  • لا يكتمل الاسترداد قبل تأكيد التنفيذ الفعلي وإشعار العميل.
المخزون والتوصيل · FR-049–FR-061
  • إدارة كمية المخزون يدوياً مع حركات وارد وصادر.
  • تسجيل سبب الحركة والموظف والتوقيت والملاحظات.
  • تنبيه انخفاض المخزون وحد إعادة الطلب قابل للتعديل.
  • منع تجاوز الكمية المتاحة والتحقق من المخزون على الخادم.
  • إدارة مناطق التوصيل داخل محافظة السويداء.
  • رسوم ثابتة للمدينة ورسوم قابلة للتحديد للقرى والمناطق.
  • إعداد حد أدنى للطلب وحد التوصيل المجاني من لوحة الإدارة.
  • إعادة احتساب رسوم التوصيل عند تعديل محتويات الطلب.
  • إسناد الطلب لمندوب الصيدلية أو شركة خارجية عند الحاجة.
  • الإدارة تحدث حالات التوصيل؛ لا يتطلب النطاق الحالي حساباً للمندوب.
  • Timeline للعميل يوضح الحالات وتاريخ ووقت كل انتقال.
الحساب والمفضلة والإشعارات والمحتوى · FR-062–FR-070
  • قائمة مفضلة لكل عميل مسجل، مع الإضافة والإزالة والعرض والنقل إلى السلة.
  • استمرار المفضلة بين الجلسات.
  • لا يوجد نظام تقييمات أو مراجعات.
  • إشعارات داخل الموقع عند تغير الحالة أو الحاجة لإجراء.
  • WhatsApp للإشعارات وSMS بديلاً عند عدم توفر WhatsApp.
  • إدارة بنرات الصفحة الرئيسية وصور العروض وروابطها.
  • اختيار منتجات الصفحة الرئيسية والتحكم بالأقسام وإظهارها أو إخفاؤها.
  • العربية والإنجليزية مع RTL/LTR.

قواعد العمل الأساسية

08 · BR-001–BR-022
الحساب والعملة

الشراء يتطلب حساباً؛ التصفح متاح للزوار. العملة الوحيدة لكل الأسعار والطلبات والفواتير والرسوم والخصومات والمدفوعات والاستردادات هي SYP.

النطاق الجغرافي

نطاق التوصيل الحالي محافظة السويداء فقط.

الوصفات

لا يباع دواء يتطلب وصفة قبل مراجعة الصيدلي والموافقة. رفض دواء لا يلغي بقية المنتجات.

إعادة الحساب

بعد حذف دواء مرفوض يعاد حساب الإجمالي والخصومات ورسوم التوصيل وشروط التوصيل المجاني.

الموافقة والدفع

الطلب Pending عند الإرسال. الدفع الإلكتروني بعد موافقة الإدارة؛ والدفع عند الاستلام يبدأ تجهيزه بعد الموافقة.

مهلة الدفع

تبدأ بعد الموافقة وإشعار العميل. انتهاؤها دون تأكيد يلغي الطلب ويحرر الكميات ويخطر العميل. لا تنطبق على الدفع عند الاستلام.

الخصومات

يطبق خصم واحد فقط ويختار النظام الأفضل للعميل؛ لا تجمع خصومات المنتج والتصنيف والكوبون.

الإلغاء والاسترجاع

الإلغاء الذاتي قبل بدء التجهيز فقط. لا يوجد استرجاع اعتيادي بعد التسليم، مع مراعاة الحقوق والاستثناءات القانونية للعيب أو خطأ التنفيذ.

المخزون

يمنع تجاوز المخزون. المنتج النافد يبقى ظاهراً وغير قابل للشراء حتى توفر كمية جديدة.

الصلاحيات والتدقيق

تسجل العمليات الحساسة مع الفاعل والتوقيت والقيم السابقة والجديدة. الموظف لا يمنح نفسه صلاحيات.

العنوان والصلاحية

للعميل عنوان توصيل واحد محفوظ. الدفعة وتاريخ الصلاحية ليسا حقلاً إلزامياً عاماً.

الامتثال

بيع الأدوية والوصفات يخضع للقوانين المحلية، ولا يفترض أن جميع الأدوية قابلة للبيع الإلكتروني.

حالات الاستخدام وسير العمليات

09

التدفق العام للطلب من اختيار المنتجات حتى التسليم:

اختيار المنتجات←السلة والتحقق من المخزون←العنوان والدفع←Pending←مراجعة الإدارة←موافقة / رفض

تسلسل حالات الطلب

Pending→Confirmed→Processing→Ready for Delivery→Out for Delivery→Delivered

توجد حالة Cancelled للإلغاء مع تسجيل السبب والجهة المنفذة. يجب حفظ تاريخ ووقت كل انتقال والموظف أو العملية الآلية التي نفذته.

التسجيل والدخول

يدخل العميل الهاتف وكلمة المرور، يرسل النظام OTP، يدخل العميل الرمز الصحيح لتفعيل الحساب، ثم يتحقق النظام من بيانات الاعتماد ويطبق حدود المحاولات وإدارة الجلسات.

الدفع الإلكتروني

بعد موافقة الإدارة يُشعر العميل وتبدأ المهلة؛ وبعد تأكيد الدفع يبدأ التجهيز.

الدفع عند الاستلام

يبدأ التجهيز بعد موافقة الإدارة دون تطبيق مهلة الدفع الإلكتروني.

الوصفة

يرفع العميل صورة الوصفة، يراجعها الصيدلي ويوافق أو يرفض مع السبب. عند الرفض يزال الدواء وحده ويعاد الحساب وتستمر بقية المنتجات.

  • تخزين كلمات المرور باستخدام Password Hashing مناسب وعدم تخزينها كنص صريح.

  • إدارة الجلسات وإتاحة تسجيل الخروج من الأجهزة.
  • تطبيق RBAC في الخادم والواجهات وواجهات API والملفات.
  • Audit Logs للعمليات الحساسة وتغييرات الصلاحيات مع القيم السابقة والجديدة.
  • الموافقة على شروط الاستخدام وسياسة الخصوصية وتسجيل تاريخ وإصدار الموافقة.
  • تقييد الوصول إلى الوصفات وتخزينها في مساحة خاصة والتحقق من الملفات المرفوعة.
  • نسخ احتياطي يومي تلقائي والاحتفاظ بعدة نسخ وإمكانية الاستعادة.

معايير قبول النسخة الأولى

  • التصفح متاح للزائر والشراء يتطلب حساباً موثقاً.
  • يمكن إنشاء طلب ومتابعته من حساب العميل.
  • يمكن للإدارة الموافقة أو الرفض مع السبب.
  • رفض دواء بوصفة لا يلغي بقية المنتجات الصالحة.
  • كل المبالغ بعملة SYP.
  • لا يمكن تجاوز المخزون عبر الواجهة أو API.
  • المنتج النافد ظاهر وغير قابل للشراء.
  • تسجل حركات المخزون والعمليات الإدارية الحساسة.
  • تعمل وسائل الدفع بتكامل رسمي متاح أو إجراء يدوي موثق.
  • تعمل إشعارات الحالات وتظهر حالات فشل الإرسال للإدارة.
  • تعمل العربية والإنجليزية وRTL/LTR على الشاشات المستهدفة.
  • تتوفر نسخة احتياطية يومية وتنجح تجربة استعادة قبل الإطلاق.
هذه النسخة مسودة تأسيسية للمتطلبات التي جرى تحديدها. تصبح مرجعاً معتمداً للتطوير بعد مراجعتها وحسم القرارات المعلقة. أي توصية أو افتراض لم يعتمده صاحب المشروع صراحةً هو اقتراح قابل للنقاش وليس قراراً نهائياً.
